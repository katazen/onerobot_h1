## Current finding

The repository-level `LICENSE` is BSD-3-Clause and names `Copyright (c) 2026, 万昕`. No file was found that unambiguously establishes that this license covers the OneRobotics A1 CAD-derived robot assets or that the named holder is authorized to license those assets for redistribution.

Accordingly, this repository must not describe the URDF, MJCF/XML, STL, or any converted USD derivative as BSD-3-Clause, Apache-2.0, MIT, public domain, proprietary, or otherwise cleared until the asset rights holder or its authorized representative confirms the owner and redistribution terms in writing. This status is separate from the Python/code license.

## Provenance and third-party observations

- The prior README described the STL/URDF content as the company's A1 model, but that statement is not an explicit redistribution license or chain-of-title record.
- Each URDF says it was generated by SolidWorks to URDF Exporter and retains the generator attribution to Stephen Brawner. This identifies the generating tool; it does not license the A1 CAD geometry or the generated robot model.
- The five MJCF files contain no asset-license header. They reproduce A1 kinematic/inertial data and reference the same STL meshes, so their license scope must be confirmed together with the URDF/STL set.
- The binary STL files contain no readable embedded copyright or license notice.
- No third-party texture, material, OBJ, DAE, or other model bundle was found.

The SolidWorks exporter source is not vendored here. Its software license therefore does not replace or determine the license of the generated A1 files. See `THIRD_PARTY_NOTICES.md` for the separate source-code attribution audit.

## Git and packaging status

- `git lfs ls-files --all` returned no entries at the audited baseline.
- All 41 assets are ordinary Git blobs, not LFS pointers.
- The 33 STL files range from 20,484 to 1,553,084 bytes; none exceeds the repository's current 2,000 KiB pre-commit threshold. Phase 1 therefore does not add STL files to LFS blindly.
- Package configuration includes the assets because the external project cannot spawn the A1 or run MuJoCo without them. This packaging fix is not a license grant and does not clear publication or upstream redistribution.

The assets already exist in the public repository and are included in local wheel builds. Public visibility and technical package inclusion are forms of distribution exposure; neither is evidence of permission. Do not publish a wheel, release, mirror, or upstream copy containing these assets until the review is resolved.

## Confirmation required from the asset rights holder

Before an upstream asset submission, record:

1. the legal owner or entity authorized to license the model;
2. the exact covered source files, revisions, or hashes;
3. permission for public redistribution, modification, and commercial use;
4. coverage of generated and converted formats, including URDF, MJCF/XML, STL, and USD;
5. required copyright, attribution, trademark, and notice text;
6. any third-party CAD, mesh, material, or tooling inputs and their obligations; and
7. whether the asset license should live in this repository or a separate OneRobotics asset repository.

Only after that review should this file be replaced with the approved asset-license scope and text.
